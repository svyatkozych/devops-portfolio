# Project 1: DevOps Sentinel 🛡️

## 1. Проблема
У середовищах без належного моніторингу системні помилки, критичне навантаження на процесор, переповнення дискового простору, збої фонових завдань (cron) або недоступність ключових сервісів залишаються непоміченими доти, доки не призведуть до повної зупинки системи чи втрати даних. Ручний моніторинг є неефективним і занадто пізно виявляє проблеми.

## 2. Цільовий користувач та практична цінність
Проєкт створений для системних адміністраторів та DevOps-інженерів. Він забезпечує автономний локальний контроль критичних параметрів Linux-сервера, швидке виявлення аномалій та генерацію структурованих сповіщень.

## 3. DevOps-цінність
* Автоматизація перевірки стану інфраструктури (Health Checks).
* Проактивне виявлення збоїв замість реактивного гасіння пожеж.
* Повторюваність і стандартизація діагностики через модульні Bash-скрипти.

## 4. Архітектура та компоненти
* **`scripts/sentinel-health.sh`** — головний оркестратор перевірок.
* **`scripts/cpu-check.sh`** — моніторинг завантаження CPU.
* **`scripts/process-check.sh`** — перевірка критичних процесів.
* **`scripts/ssh-healthcheck.sh`** — контроль безпеки та доступності SSH.
* **`scripts/backup.sh`** —автоматизоване створення резервних копій.

## 6. Автоматизація та фоновий запуск (Systemd)
Проєкт підтримує автономну роботу за допомогою Linux Systemd (User Units), що дозволяє запускати моніторинг за розкладом без зайвого ручного втручання.
Інструкція з встановлення таймера локально:
```bash
# Створити директорію для користувацьких сервісів
mkdir -p ~/.config/systemd/user

# Скопіювати сервіс та таймер
cp app/systemd/sentinel.* ~/.config/systemd/user/

# Перезавантажити демона та увімкнути таймер
systemctl --user daemon-reload
systemctl --user enable --now sentinel.timer

# Перевірити статус таймера
systemctl --user status sentinel.timer
